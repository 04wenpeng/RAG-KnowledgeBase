# RAG 知识库 · 使用说明 FAQ

本文件既是示例文档（用来演示 Markdown 加载），也是这个知识库自己的说明书。

## 一、这个知识库是怎么工作的

整个流程分两个阶段，对应课件里的索引阶段与查询生成阶段。

索引阶段：先由文档加载器把 data 目录里的文件读成 Document 对象，再用文本分割器切成 500 字左右的块，然后调用嵌入模型把每个块转成向量，最后写入 Chroma 向量库并持久化到 store 目录。

查询阶段：用户提问后，先把问题向量化，在向量库里做相似度检索取回最相关的若干片段，再把片段和问题拼成增强提示词，交给大语言模型生成带出处的答案。

## 二、如何加入自己的资料

把 pdf、docx、txt、md、csv、xlsx 文件直接复制到 data 目录，然后重新运行建库脚本即可。新增资料建议加 `--reset` 参数做全量重建，避免旧内容残留。

单个文件超过一百页时，建议先用 `--chunk-size 800 --overlap 80` 建库，让每块保留更完整的上下文。

## 三、召回数量该怎么调

召回数量就是 Top-K。默认取 4。答案里缺少细节时把它调大，例如 6 到 8；答案里混进无关内容时把它调小到 2 或 3。

Top-K 越大，送进大模型的上下文越长，速度越慢、费用越高，所以不建议盲目调到十以上。

## 四、为什么有时候回答是“抽取式”的

没有配置大模型 Key 时，系统不会调用任何外部接口，而是从命中的片段里抽取最相关的句子拼成答案，并在句末标注来源编号。这种方式完全离线、可追溯，但不会做语言润色和推理。

在项目根目录的 .env 文件里填上 DASHSCOPE_API_KEY，重启程序后就会自动切换为大模型生成。

## 五、怎么给别人用（怎么分享给别人、别人怎么访问、发给同事的链接）

常见问法：怎么给别人用、怎么分享给别人、别人怎么访问、发给同事的链接是什么、同事怎么用这个知识库。

怎么给别人用，答案就一句：把下面这个链接发给对方，对方在浏览器里粘贴、回车就能用。

发给别人的链接：http://DESKTOP-M0B255V:8000/

## 六、怎么启动和停止

常见问法：知识库怎么启动、服务怎么启动、怎么打开知识库、启动不了怎么办、服务停了、怎么停止、怎么重启、开机自启吗。

启动：双击项目根目录的 `8-后台启动.bat`。它会在后台拉起服务并自动打开浏览器，关掉黑框也不影响。

停止：双击 `9-停止服务.bat`。

看状态：命令行运行 `python src\tools\service_task.py status`。

打不开网页时先跑 `7-诊断.bat`，它会检查端口、HTTP 连通性、代理和索引。

## 七、怎么换模型

常见问法：怎么换模型、怎么切回 DeepSeek、用哪个模型、能不能离线用、模型在哪儿配、换模型要不要重建索引。

打开 `http://127.0.0.1:8000/config` 配置页，列表里每一套配置后面都有「启用」按钮，点一下就用那套。

现在有两套：本机 Ollama 跑的 qwen-local 小模型（断网也能用），和 DeepSeek 官方接口（需要联网和 Key）。切换不需要重建索引。

只有在更换嵌入模型时（比如从离线哈希向量换成百炼 text-embedding）才必须重建索引。

## 八、给别的 AI Agent 用

常见问法：怎么让别的 Agent 用、Agent 怎么接、MCP 怎么配、Claude Code 怎么用知识库、插件怎么装。

本机已经配好两个：Claude Code 用 `claude mcp add` 注册了 rag-kb 这个 MCP 服务，Codex CLI 写在 `~/.codex/config.toml` 里。配好后直接对 Agent 说「用知识库查一下某事」，它会调用 ask_knowledge_base 工具。

别的电脑用的话，把 `dist\rag-agent-kit.zip` 发过去，解压后双击 check.bat 自检，再用 ask.bat 提问，或者按里面的说明配 MCP。

读接口不需要口令；只有上传资料需要管理员口令。

## 九、支持哪些文件格式

常见问法：支持哪些文件格式、能放什么文件、pdf 可以吗、word 可以吗、excel 可以吗、日志会不会被吞。

支持 pdf、docx、txt、md、markdown、csv、xlsx、json 八种。

日志文件、临时文件、md5 校验清单会被自动跳过；纯文本超过 0.5MB 也会跳过（防止把日志吞进来）。被跳过的文件会记在资料库页顶部的「最近跳过的文件」里，写明原因。

## 十、公司内部长期使用（地址稳定、手动启动、手动备份）

发给同事的固定链接用主机名，不要用 IP：http://DESKTOP-M0B255V:8000/ 。IP 会随路由器变，主机名不会。局域网地址是 http://172.22.124.143:8000/ ，Radmin 地址是 http://26.94.195.90:8000/ 。

服务不会随开机自动启动，也没有注册任何计划任务：电脑重启后服务不会自己起来，需要你手动双击 `8-后台启动.bat` 启动一次。常见问法：重启后会自动启动吗、开机自启吗、会不会自己起来、重启电脑还要不要手动开——答案都是不会，要手动启动。

停止服务：双击 `9-停止服务.bat`，服务和本地模型会一起停掉。

停止服务：双击 `9-停止服务.bat`。

备份要手动执行：运行 `python src\tools\backup.py` 会把 data 和 config 打包到 backups 目录，并自动保留最近 10 份；查看已有备份运行 `python src\tools\backup.py --list`。系统里没有注册任何自动备份的计划任务。

查看运行状态：命令行运行 `python src\tools\service_task.py status`，会显示服务是否响应、索引块数、当前模型、最近一次备份（任务计划里没有注册任何自启项）。

注意事项：关机或睡眠时同事就连不上；重启电脑后要记得手动启动；只把管理员口令 123456 给需要改配置的人，普通同事只发链接，不要给口令。

## 十一、换嵌入模型必须重建索引

索引里存的向量是某个嵌入模型产出的。换了嵌入模型，向量空间就变了，旧向量和新问题对不上，检索结果会变得完全无关。

所以更换嵌入模型后，务必执行 `python ingest.py --reset` 重建整个索引。

## 十二、使用说明会不会自动进知识库

会。每次重建索引（网页点「重建索引」、跑 `src\ingest.py`、以及 Agent 调重启接口）之前，系统会先自动把项目里的说明文档同步到 `data\项目说明\`，再统一切块入库。

自动同步的文档有四个：`AGENTS.md`、`src\README.md`、`src\agent\README.md`、`src\agent\AGENT_INSTRUCTIONS.md`。操作类问答（怎么分享、怎么启动、怎么换模型、怎么备份等）统一由 `data\使用说明-FAQ.md` 负责，它本身就在 data 目录里，改完重建索引即可。

所以改了说明文档之后，只要重建一次索引就自动进库，不需要单独跑同步脚本。想先看有没有差异可以运行 `python src\tools\sync_docs_to_data.py --check`。

`README.md` 和 `dist` 目录里的分发说明故意不同步：它们和 FAQ 内容重叠，实测会把「怎么给别人用」这类问题的答案挤掉。

## 十三、文档更新后怎么做增量

每个文本块都有稳定的 id，格式为“文件名#页码#块序号#全局序号”。文档内容变化后，用 `--reset` 重建最稳妥；数据量大时，可以先按文件名过滤删除旧块再追加新块。

## 十四、怎么自检答案质量

运行 `python src\tools\test_quality.py` 会跑 12 个典型问题，分三类：资料类（问文档里的技术细节）、操作类（问这个库怎么用）、以及和资料无关的问题。

期望结果：前两类给出内容并带出处，第三类必须明确说无法回答。目前 12 个全部通过。

如果某题变红，常见原因：一是说明文档没同步（重建索引会自动同步），二是检索阈值或降权规则被改动过。

提醒：写文档时不要在正文里引用真实的提问原句，否则检索时会把「示例」当成答案。

## 十五、检索不准怎么办

先判断是没召回还是召回了没用上。用 `python ask.py --retrieve-only "问题"` 只做检索，人工看命中的片段里到底有没有答案。

如果片段里根本没有答案，说明分块或嵌入模型不合适，要调 chunk_size、换中文分隔符或换嵌入模型。

如果片段里有答案但回答错，说明提示词或 Top-K 需要调整，重点检查提示词里是否明确要求“只依据已知信息回答、找不到就说无法回答”。

## 十六、数据会不会上传

建库和检索都在本机完成。只有配置了大模型并启用生成时，检索到的片段才会随提示词发送给对应的大模型服务商。不配 Key 的情况下全程不出本机。
